# SBOM and build provenance

## SBOM (`SBOM.spdx.json`)

SPDX 2.3 JSON, generated by `scripts/ci/release_tool.py sbom` in `release.yml` from:

| Source | Content | SPDX relationship |
|---|---|---|
| `:ui:writeReleaseDependencies` (resolved `releaseRuntimeClasspath` + `coreLibraryDesugaring`) | Maven libraries shipped in the app, with resolved versions and `pkg:maven` purls | app `DEPENDS_ON` |
| `tunnel/tools/libwg-go/go.mod` | Go modules compiled into `libwg-go.so` (direct and indirect), `pkg:golang` purls | app `DEPENDS_ON` |
| `git submodule status` + `.gitmodules` | `amneziawg-tools` (compiled into the app) and `elf-cleaner` (build tool), at their commit SHAs | `DEPENDS_ON` / `BUILD_DEPENDENCY_OF` |
| Gradle wrapper, version catalog, `settings.gradle.kts`, `go.mod` | Gradle, Android Gradle Plugin, Kotlin, NDK, build-tools and Go versions | `BUILD_DEPENDENCY_OF` |
| Release files | Each APK and the AAB with its SHA-256 | `GENERATED_FROM` the app |

Limitations: licenses are `NOASSERTION` (not resolved); Go module hashes from `go.sum` are not
included (they are not SHA-256 file digests); the NDK's own components are not itemised.

The workflow validates the structure (required fields, unique SPDX IDs, resolvable relationships,
SHA-256 format) with `release_tool.py validate-sbom`. For a full validation with the SPDX reference
tools:

```sh
pip install spdx-tools
pyspdxtools -i SBOM.spdx.json
```

(This independent validation has not been run on a real release SBOM yet.)

## Build provenance

`release.yml` runs `actions/attest-build-provenance` for every APK and the AAB. GitHub records a
signed SLSA provenance statement (Sigstore) that ties each file's SHA-256 digest to the repository,
commit, tag, workflow file and run, and the runner environment. Required permissions are
`id-token: write` and `attestations: write`, granted only to the release job.

Availability: artifact attestations work for public repositories, and for private repositories only
on GitHub Enterprise Cloud. If attestation fails, the release continues; `release.json`
(`provenance.github_attestation: false`) and the release notes then say so.

### Verifying provenance

```sh
gh attestation verify routevpn-1.0.4-arm64-v8a.apk --repo RouteTechnologies/amneziawg-android
```

The output shows the workflow, commit and tag that built the file. Self-hosted runners are recorded
as such; provenance from a self-hosted runner is only as trustworthy as that runner.

`release.json` additionally records the commit, tag and workflow run URL (unsigned metadata).
